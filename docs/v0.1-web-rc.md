# V0.1 Web Release Candidate

## 目标

V0.1 RC 不再增加核心玩法系统，目标是把当前 Integration 构建变成可重复验证、可分发、可安装的 Web/PWA 候选版本。

当前包版本：

```text
0.1.0-rc.1
```

## Web / PWA 包装

V0.1 RC 使用原生 Web 平台能力，不增加新的运行时依赖：

- `manifest.webmanifest`
- `icon.svg`
- `sw.js`
- `viewport-fit=cover`
- `display: standalone`
- 相对 `start_url` / `scope`

Service Worker 只在 Production 且非 localhost 环境注册。

缓存策略：

- App Shell：install 时预缓存；
- Navigation：Network First，离线时回退缓存首页；
- 同源静态资源：Cache First + 后台刷新；
- 新版本 Service Worker 激活时清理旧 Rogue Defense Cache。

Vite 继续使用：

```text
base: './'
```

因此同一个 `dist/` 可以放在站点根目录、GitHub Pages 子路径或未来 Android WebView/Capacitor 包装中。

## Browser Smoke Gate

CI 在 Production Build 后临时安装固定版本 Playwright + Chromium，并运行真实浏览器 Smoke Test。

测试覆盖：

1. Production Preview 可以加载 Canvas，浏览器无 `pageerror` / console error；
2. 正常 W1 Run 可以启动；
3. 正常 W1 主动结算会写 Permanent Save；
4. DEV W100 + Stress 300 可以真实进入 Combat；
5. Runtime Probe 确认 `Wave=100`、`Stress=300`、Enemy Count >= 300；
6. DEV Settlement 不修改 `rogue-defense.save`；
7. 390×844 手机竖屏视口可以显示 Canvas 并通过触控坐标启动 Run；
8. `manifest.webmanifest` / `sw.js` / `icon.svg` 在 Production Preview 可访问。

CI Commit Status：

```text
ci/build
ci/smoke
```

只有两者都通过，当前提交才视为 Web RC 自动验证通过。

## Runtime Probe

`src/dev/RuntimeProbe.ts` 只在以下条件启用：

```text
Vite DEV
或
URL ?dev=1
```

测试信息写入：

```text
#app.dataset
```

可见字段包括：

- Scene
- Wave
- Enemy Count
- Projectile Count
- DEV Run
- Start Wave
- Stress Count

普通 Production URL 不发布这些调试字段。

## CI Web Artifact

当 `ci/build` 与 `ci/smoke` 都成功时，CI 上传：

```text
rogue-defense-v0.1-rc1-web
```

内容为完整 `dist/`，保留 14 天。

这个 Artifact 不依赖 GitHub Pages，可用于：

- 本地静态服务器试玩；
- 交给测试设备；
- 未来部署到任意静态 Hosting；
- Android WebView/Capacitor 包装前的输入构建。

## GitHub Pages

仓库已准备：

```text
.github/workflows/pages.yml
```

工作流使用 GitHub Pages 官方 Artifact → Deploy 流程，并保持 `workflow_dispatch` 手动触发。

原因：当前仓库为 Private。Pages 是否可用于 Private Repository 取决于 GitHub 账户/组织方案与仓库 Pages 设置；自动把仓库改成 Public 不属于 RC 构建行为。

若当前 GitHub 账户支持 Private Pages，只需在 Repository Settings → Pages 中把 Source 设置为 GitHub Actions，然后手动运行：

```text
Deploy Web RC to GitHub Pages
```

若当前方案不支持 Private Pages，仍可直接使用 CI Web Artifact，或未来在明确决定后改为 Public / 使用其他静态 Hosting。

## PWA 边界

V0.1 RC 的 PWA 目标是“可安装 + 基础离线 App Shell”，不是完整离线长局产品承诺。

当前不做：

- 云存档；
- 多设备同步；
- Background Sync；
- Push Notification；
- 大型资产版本管理；
- 离线更新提示 UI。

## Release Candidate Gate

自动 Gate：

```text
TypeScript strict
→ Vite Production Build
→ Chromium Browser Smoke
→ Web Artifact
```

仍必须人工验证：

- W1 → W100 真长局；
- W100 Boss → Shop → W101；
- 300 Enemy + 4× 真机 FPS；
- Android Chrome；
- iOS Safari；
- 横屏；
- PWA 安装/重启；
- Service Worker 更新；
- 长局内存；
- 第一轮平衡。

只有这些关键运行时项目达到可接受状态后，才从 `0.1.0-rc.1` 升为正式 `0.1.0`。
