# V0.1 Playtest / Performance Tools

## 目标

V0.1 Integration 第二阶段不新增主要游戏系统，重点是提高长局验证效率、降低高敌人数 UI 开销，并让手机触控测试不依赖键盘。

## DEV Mode

开发工具只在以下任一条件成立时显示：

```text
Vite local development (`import.meta.env.DEV`)
或
URL 带 ?dev=1
```

正式普通访问不会显示 DEV LAUNCH 面板。

示例：

```text
https://<host>/?dev=1
```

## 快捷 Wave 启动

Main Menu 的 DEV LAUNCH 支持：

```text
W1
W10
W20
W50
W80
W100
```

选择后点击“开始一局”，CombatScene 会直接从指定 Wave 初始化。

用途：

- W10：Boss Shop 基线；
- W20：首次 Air Escort；
- W50：中期 Build / Scaling；
- W80：后期压力；
- W100：Boss → Shop → W101 / 难度解锁链验证。

快捷启动不会模拟此前已经取得的武器、升级或经济，因此它主要用于系统流程、Boss、敌人数值与性能验证，不等价于真实 W1→目标 Wave 的平衡测试。

## DEV Run 不写永久 Save

只要满足：

```text
Start Wave != 1
或
Stress Count > 0
```

该局标记为：

```text
DEV Run
```

DEV Run 可以进入正常 Settlement 预览 Gold / Account EXP / Difficulty Unlock 结果，但 Settlement 在克隆的 Save 上执行，不写回 `rogue-defense.save`。

因此 DEV W100 不会：

- 解锁 Difficulty；
- 写 High Wave；
- 增加 Gold；
- 增加 Account EXP；
- 增加 Lifetime Stats。

结算页显示：

```text
DEV PREVIEW · 永久存档未修改
```

## 300 Enemy Stress

DEV LAUNCH 可开启：

```text
Stress 300
```

启动后额外创建 300 个测试敌人。

测试敌人按当前 Wave Scaling 与 Difficulty Scaling 生成，但：

```text
不发 EXP
不发 Combat Credits
不增加正常击杀统计
```

W20+ Stress 会混入 Flying，其他敌人以 Infantry / Heavy 为主。

建议性能检查：

```text
W1 + Stress 300
W50 + Stress 300
W100 + Stress 300
```

重点观察：

- FPS；
- Projectile Active / Pool Size；
- Targeting 是否持续工作；
- Status / Combo 是否出现明显卡顿；
- 4× 时输入与 Overlay 是否仍可用。

## Projectile Pool 优化

ProjectilePool 保持对象池架构，并新增：

```text
activeCountValue
size
clear()
```

过去 HUD 每次读取 Active Count 都遍历整个 Projectile 数组；现在 `update()` 在原本必须遍历 Projectile 的同时缓存 Active Count，因此 HUD 查询为 O(1)。

初始 Projectile Pool：

```text
384
```

耗尽后仍允许扩容，优先保证战斗逻辑不丢弹。

## Enemy Status Badge 优化

旧版本每个 Enemy 出生时都会创建隐藏的 Phaser Text 状态标签，并在每 Frame 更新文本。

V0.1 第二阶段改为：

```text
无 Status
→ 不创建 Status Text

首次获得 Status
→ Lazy Create

状态显示刷新
→ 150 ms 周期

状态文本未变化
→ 不重复 setText()
```

直接伤害、移动、Burn Tick 和 StatusEffectSystem 本身仍按正常 Simulation Delta 更新；只降低可视状态文字刷新频率。

## HUD 刷新节流

Combat Simulation：

```text
每 Frame
```

HUD：

```text
100 ms 一次
```

玩家完成升级、商店购买、速度切换等明确交互后仍立即刷新 HUD。

这样 Enemy Count / Heavy Count / Air Count / FPS / Projectile Count 不再每 Frame 做 UI 文本重建。

## Touch Speed Controls

Combat HUD 正式加入：

```text
1×  2×  3×  4×
```

触控按钮与键盘 `1～4` 使用同一个 `setGameSpeed()`，继续受永久科技 `speed-control` 限制。

锁定速度显示为：

```text
2× L
3× L
4× L
```

Overlay Pause 时 Simulation 不推进，与速度按钮无冲突。

## Mobile Viewport

页面采用：

```text
100dvw / 100dvh
viewport-fit=cover
Safe Area Insets
overscroll-behavior: none
touch-action: none
```

用于降低：

- iOS Safari 地址栏导致的高度变化；
- 刘海/圆角遮挡；
- 页面滚动和双指浏览器手势干扰；
- Canvas 触控高亮。

Combat World 仍保持统一 `1000×1600` 逻辑坐标，设备只负责 Phaser FIT 缩放。

## 仍需真实运行验证

自动 CI 不能替代以下检查：

- W1→W100 真长局；
- DEV W100→Boss Shop→W101；
- 300 Enemy + 4× 的真实 FPS；
- iOS Safari / Android Chrome Safe Area；
- 横屏 Canvas 尺寸和可读性；
- 长时间运行内存增长；
- Projectile Pool 在高攻速 Build 下的峰值大小；
- Status/Combo 密集触发时的 GC / Frame Spike。
