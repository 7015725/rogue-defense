# V0.1 Real-Device Web Test Guide

## 当前结论

V0.1 RC 已具备第一轮手机浏览器实机测试条件，并且自动性能前置已经通过：`ci/perf = success`、`ci/soak = success`。Fixed Stress300 的 W1/W50/W100 每档独立采样 3 次取中位数，当前均为 20 FPS，自动最低 Gate 保持 15 FPS。

**因此 Android Chrome / iOS Safari 的第一轮实机 Web 测试现在即可开始。**

Android APK 尚未封装；APK 实机安装测试放在 Web RC 的触控、真机性能和长局问题收敛之后。

## 同一局域网测试

电脑与手机连接同一 Wi-Fi。

```bash
npm install
npm run build
npm run preview:lan
```

终端会启动 Vite Preview，默认端口为 `4173`。在手机浏览器访问：

```text
http://<电脑局域网IP>:4173/
```

DEV 测试入口：

```text
http://<电脑局域网IP>:4173/?dev=1
```

> 局域网 HTTP 可以验证游戏、触控、横竖屏、Save 和性能，但 Service Worker / PWA 安装需要 HTTPS 安全上下文，因此 PWA 安装测试应在 GitHub Pages 或其他 HTTPS 部署完成后进行。

## 第一轮实机测试顺序

1. 正常 W1 启动，确认主菜单、战场和字体可读。
2. Portrait 模式检查 Canvas 是否完整落在可视区域内。
3. 测试 1× / 2× / 3× / 4× 触控按钮及科技锁定状态。
4. 触发三选一，验证卡片、重抽、Skip 的触控区域。
5. 触发武器 Lv5 / Lv10，验证路线卡片触控。
6. DEV W10/W20 进入 Boss Shop，验证购买、刷新、离店。
7. 满随机武器槽后验证 Replacement Overlay。
8. 刷新页面，确认 Permanent Save 保留。
9. `?dev=1` 分别测试 W1 / W50 / W100 + Stress300，记录 HUD FPS、触控响应和发热情况。
10. Portrait 与 Landscape 各完整操作一次。

## Android Chrome 验收

- [ ] Portrait 主菜单完整可见
- [ ] Landscape 不出现不可操作区域
- [ ] Canvas 无页面滚动/回弹干扰
- [ ] Speed Buttons 触控正常
- [ ] Upgrade Overlay 触控正常
- [ ] Weapon Branch Overlay 触控正常
- [ ] Boss Shop 触控正常
- [ ] Weapon Replacement 触控正常
- [ ] 刷新后 Save 正常恢复
- [ ] W1 + Stress300 可运行
- [ ] W50 + Stress300 可运行
- [ ] W100 + Stress300 可运行
- [ ] 4× 下触控仍可响应
- [ ] 10 分钟运行无明显持续内存/温度异常

## iOS Safari 验收

- [ ] Portrait 主菜单完整可见
- [ ] Landscape 不出现不可操作区域
- [ ] Safe Area 未遮挡关键按钮
- [ ] Canvas 不触发页面滚动/缩放手势
- [ ] Speed Buttons 触控正常
- [ ] Upgrade / Branch / Shop / Replacement 触控正常
- [ ] 刷新后 Save 正常恢复
- [ ] W1 / W50 / W100 + Stress300 可以进入
- [ ] 4× 下触控仍可响应

## PWA / HTTPS 阶段

GitHub Pages 或其他 HTTPS 地址可用后，再验证：

- Service Worker 注册
- Add to Home Screen / Install
- Standalone 启动
- Safe Area
- 离线 App Shell
- Service Worker Cache 更新

## APK 阶段

Web RC 完成关键真机问题修复后，使用同一代码库接 Capacitor，进入 Android APK 测试。首轮 APK 只做 WebView 容器、全屏/返回键/生命周期/存档兼容，不重新改战斗核心系统。
